Timekeeper 0.2.1 build notes
=========================

This first Windows build implements the file exchange workflow using the Quickbase Case Manager schema from the reference material. It is a native WPF/.NET 10 application with a per-user Windows installer and a bundled runtime. End users do not need Python, a console, or a separate .NET installation.

The installer is built at `artifacts/installer/Timekeeper-Setup-0.2.1-win-x64.exe`. Its adjacent `SHA256SUMS.txt` is generated by the build script. Release artifacts are also published to GitHub. The installer itself has not been installed on this computer.

Implemented:

- Account settings, read-only connection/identity tests, Windows Credential Manager storage, per-user time preferences, timezone and internal project/task settings.
- Today and date-range reads, complete Quickbase pagination checks, source IDs and exact duration preservation, explicit date boundaries, running/overnight-timer checks, and request pacing.
- A real draggable JSON export; a shared Copilot agent link; returned-file drag/drop, file picker, and JSON paste. Agent setup is maintained once by the owner using source-repository instructions.
- Strict proposal schema, source-session and employee checks, complete source coverage, trusted relationships, local rounding and automatic additions, and explicit warning acknowledgment.
- Full review table and row details, daily totals, explicit Write action, fresh-data checks, durable submission receipts, replay protection, and reconciliation.
- Assignment search with updated exports, local history, and synthetic demo mode with writes disabled.
- Automatic detection of the Quickbase token owner's user ID, with email and identity verification.
- No user ID field in Settings. Connection results show the accounts to confirm; a token-help link and Getting started guide cover user setup.
- Explicit update checks, stable-version comparison, bounded downloads, SHA-256 verification and an installer launch that preserves application data. Private GitHub access can be configured separately in Windows Credential Manager.

The user's rule is implemented: default 7.00 hours + 0.17 Timecards + 0.83 Misc internal = 8.00; default 9.00 hours + 0.17 Timecards = 9.17. Both settings are configurable. Clock time has no role in the fill calculation. Existing Timecards is counted once, weekends use actual work only, and empty days receive no automatic additions.

Verification completed during development:

- Release compilation with zero warnings/errors.
- 48 offline rules/schema cases, including the confirmed hours policy, rounding, malformed proposals, source coverage, already-recorded links, duplicate warnings, stale reads, and assignment warnings.
- 39 mocked API/storage/submission cases, including automatic identity discovery, shared-agent setting migration, pagination, source changes, daylight saving, overnight/running timers, journal persistence, partial/unknown outcomes, reconciliation, replay prevention, and warning acknowledgment.
- 18 updater cases covering version checks, release metadata, private-access errors, redirects, token isolation, verified downloads, truncation, checksum failure and cancellation.
- WPF smoke checks for demo loading, real export/import files, proposal validation and row display, invalid-import approval reset, warning gating, disabled demo writes, automatic identity setup and update controls.
- Rendered interface inspection for the main screen and settings. The smoke command uses synthetic data in its specified output folder and does not access credentials or call services.

Reproduce the application smoke check after building:

```powershell
./artifacts/publish/Timekeeper.exe --smoke-test ./artifacts/published-ui-check
```

The installer pipeline is in `scripts/build.ps1`; it publishes only the application and the new guides. Historical scripts, personal reference outputs, tokens, local settings, and receipts are excluded.

Remaining verification and limitations:

- Live credentials, the configured Quickbase schema, native file transfer into the user's Copilot host, and an approved live write have not been tested. No live timecards were created during this build.
- The installer is unsigned. Compilation and application smoke checks do not constitute an installation/uninstallation test on a clean Windows machine.
- In-app Microsoft 365 sign-in/chat is deferred; the user's available Agent Builder workflow opens in the browser.
- The app uses the reference schema's field IDs. Editable table IDs alone do not adapt it to an unrelated Quickbase schema.
- Copilot's downloadable file must be saved locally if direct dragging from the browser supplies a link instead of a file.
- Cross-midnight work must be split in Toggl before submission; the app does not silently allocate its duration across dates.
- The local receipt journal prevents replay from this installation. It cannot guarantee exactly-once creation across multiple devices without a server-side unique source/submission field.
- An uncertain write with no unique new matching record remains blocked. Investigate with a Quickbase administrator; the app does not assume that a timeout means no write occurred.
- Settings, exports, receipts, and credentials are retained when the application is uninstalled, as described in the setup guide.

Start with **Try a sample day**, configure the user's own accounts in **Settings**, and use the team's shared agent link. **Getting started** covers the team workflow. The owner replaces the existing agent's legacy instructions with `docs/COPILOT_AGENT_INSTRUCTIONS.txt`; team members do not create or maintain agents.
