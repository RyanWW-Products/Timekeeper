TIMEKEEPER EMAIL EXPORT AGENT IMPORT FORMAT
CONTEXT FILE 2 - UPLOAD AS AGENT KNOWLEDGE
Revision: 2026-10-14 | Minimal machine import | Timekeeper 0.8.0+ workflow

PURPOSE
Excel only carries approved work into Timekeeper. Word is the sole generated review document. Generate Word, obtain one explicit approval of the proposed work and limitations, then generate this workbook. Do not produce a review Excel, an alternate Activities workbook or a second export schema. Older formats remain readable by the application only for backward compatibility.

1. REQUIRED APPROVAL
The employee must approve the Word report's work, underlying whole minutes, billing, account, dates/timezone and disclosed limitations. Missing source IDs do not block this format. Missing approval does. A download, silence or a request for Excel without approval is insufficient. Set employee_confirmed=true only after actual approval; the app's final review confirmation is not a substitute.

Resolve disputed timed work or identify an explicitly approved subset in Word. Accepted retrieval gaps may remain disclosed in Word. Do not silently omit activities to pass validation. No supported approved work means there is nothing to import.

2. FILE AND SHAPE
Create a real Office Open XML .xlsx with exactly two case-sensitive sheets:
Metadata
Timecards

Filename: timekeeper-email-YYYY-MM-DD.xlsx, or timekeeper-email-YYYY-MM-DD-to-YYYY-MM-DD.xlsx for a range. Workbook filename is not a duplicate-protection key.

Use row 1 for exact headers and contiguous data rows below. Plain stored values only. Do not add title rows, hours, totals, subtotals, evidence IDs, activity IDs, schema versions, generated timestamps, reporting-period fields, confidence, notes, coverage, communication accounting, formulas, macros, external links, merged cells or extra sheets/columns. No hidden review content. Use simple cell values without named formulas or defined names; formatting is unnecessary.

Limits: 10 MiB file, 32 MiB expanded package, each XML part below 8 MiB, 1-1,000 timecard rows, at most 31 inclusive calendar dates, and no more than 1,440 underlying minutes on any date.

3. METADATA
Exact headers in A1:B1:
key,value

Exactly four keys, one per row; use this order:
format,timekeeper_email_import
employee_email,the employee's verified Quickbase sign-in email
time_zone,the Windows or IANA timezone equivalent to the Timekeeper profile
employee_confirmed,true

The employee_email and timezone must match the verified Timekeeper account. A Microsoft 365 mailbox address may differ from the Quickbase address; do not assume they are equal when unknown. Never export credentials. employee_confirmed may be a Boolean true or text true. Prefer these forms over numeric substitutes.

Timekeeper derives the reporting period from actual Timecards dates. Do not add period_start, period_end, schema_version, generated_at_utc or retrieval_limitations. Coverage and approval context belong in Word.

4. TIMECARDS
Exact A1:G1 headers in this order:
date,minutes,matter_hint,assignment_hint,task_hint,description,billable

date: local work date, preferably literal YYYY-MM-DD text. The app also understands normal Excel dates, Excel serials and unambiguous date text, but the agent should export ISO to avoid locale errors. Date context is the employee's timezone, not the date of a quoted email or latest thread update.

minutes: approved positive whole minutes for this activity before application rounding. Numeric cells or numeric text are accepted. Maximum 1,440 per row, with at most 1,440 per date. Do not supply decimal hours, time-of-day durations, a formula, negative/zero values or rounded policy allocations.

matter_hint: required descriptive matter/project/internal name, at most 1,000 characters. Include a known case/project display number if useful, but never manufacture one or treat it as a Quickbase record ID.

assignment_hint: optional descriptive assignment name or useful matching hint, at most 1,000 characters. Blank if unknown. Do not put a guessed Quickbase relationship ID here.

task_hint: optional descriptive task name or hint, at most 1,000 characters. Blank if unknown. Keep a non-billable meeting under its actual matter/assignment/task when that is the approved classification.

description: required concise account of what this employee did, at most 4,000 characters. Use the approved action-oriented description. No raw emails, signatures, unrelated personal details or review caveats that obscure the work. Keep important caveats in Word.

billable: true for explicit billable work; false for explicit non-billable work; blank for deliberate Quickbase default. Prefer Boolean cells or lowercase true/false text. Blank does not mean false. The app tolerates ordinary billing labels, but these three canonical values are the generation contract. An override depends on the employee's Quickbase permission. Do not silently replace an approved false with blank to avoid a permission error.

Group compatible work before export. Keep separate rows for different dates, matters, assignments, tasks or billing. Do not count an individual message's work multiple times. Source evidence and any split rationale stay in Word/working ledgers. Stable message IDs are not required or exported in this format. With no per-row measurement-evidence fields, the app conservatively treats these rows as employee-confirmed estimates; a Word statement of measured effort does not change that import classification.

5. TIME AND POLICY
The workbook contains underlying approved work minutes, without added rounding. Timekeeper groups matched work and applies the employee's chosen rounding: no additional rounding, 5 minutes (default), or 15 minutes. Word may show separate quarter-hour planning figures; export the underlying minutes, not those figures.

Do not export automatic Timecards or Misc internal policy filler. Timekeeper's email daily additions are off by default; the employee can enable configured Timecards and weekday fill. Actual supported internal work is an ordinary Timecards row. Word distinguishes evidence-backed work, existing time, rounding and proposed additions so no allocation is counted twice.

6. TEMPLATE AND EXAMPLE
Timekeeper Email Import Template.xlsx demonstrates this exact shape with fictional sample rows. Replace all sample data, including employee identity, dates, matter names, descriptions and billing. Its employee_confirmed=false is intentional and prevents accidental import. Set true only after the actual employee approves their actual report. The template itself is not an approved day or evidence.

Illustrative Timecards rows, not employee evidence:

2026-10-12 | 15 | Example case | Intake | Meeting | Participated in intake meeting as an additional case manager. | false
2026-10-12 | 10 | Internal |  |  | Updated the internal scheduling checklist. | [blank]

7. DUPLICATE LIMITATIONS
The app calculates local row fingerprints from normalized employee, date, matter, assignment, task and description. Fingerprints exclude minutes, billing and row order so editing those values or moving rows does not turn the same work into new work. Filenames also do not make work new. Fingerprints are not source-message identifiers and cannot reliably recognize changed descriptions/hints, regrouped work, work imported through another format, or records created elsewhere.

Two otherwise identical rows are treated as duplicates even if their minutes or billing differ. Distinct real activities need truthful descriptions of the distinct work. Do not invent meaningless variations, IDs or grouping merely to bypass a warning.

Keep unchanged approved descriptions and grouping stable on export. Never edit them to bypass a duplicate warning. Check live existing Quickbase time and saved receipts. Already-recorded work should be linked to its actual record during app matching. Partial/unknown submissions must be reconciled before resubmission; deleted records use the app's recovery flow. Do not blindly create a replacement workbook.

8. FINAL CHECK AND HANDOFF
Verify exactly two sheets, four Metadata keys and seven Timecards columns. No formulas or supplementary review content. Compare every exported date, minute allocation, work description and billing value with the latest approved Word proposal. Confirm the sum of exported minutes equals the approved underlying work represented in the workbook, with all exclusions and already-recorded rows clearly identified in Word. Projected rounding and policy additions are intentionally absent.

Save and reopen the file when tools allow, then attach a real download. Reuse the reconciled approved work instead of repeating mailbox retrieval. Do not regenerate unchanged Word merely because Excel is now available. If file creation fails, disclose the failure; CSV/chat text renamed as .xlsx is not a workbook.

In Timekeeper 0.8.0+, import opens Review email activities. Assignment/task dropdowns start with editable best guesses; unmatched fields remain Choose. Check every selection and link existing records manually. Hours display as decimals (0.25 h = 15 minutes), with double-click/F2 editing. Billing follows Quickbase permissions. Optional weekday fill and Timecards controls apply to this import. Choose Review in Timekeeper dashboard, or inspect the submission preview and choose Submit directly to Quickbase. One final checkbox on the chosen review route confirms hours, mappings, estimates, coverage and duplicate limits. Word approval and employee_confirmed=true remain required. Excel continues to export whole minutes; application edits do not change this format. Generation and import do not submit automatically.
