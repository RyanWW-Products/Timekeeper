# Timekeeper 0.4.3

When a read includes multiple dates and Copilot returns a proposal for only some of them, Timekeeper now asks **Which dates do you want to submit?** You can continue with one day without mapping or resubmitting an excluded day.

- The date prompt shows each day's source coverage and existing Quickbase hours. Dates represented in the proposal start selected; you explicitly choose whether to continue, select all dates, or cancel.
- Review shows the selected and excluded dates, with a **Change dates** button. Metrics, work rows, Timecards/Misc internal additions and pre-write checks use only selected dates.
- Every source on a selected day still requires a valid mapping. Identity, source age, duplicate protection and uncertain-write checks remain enforced. Date selection never invents existing-record links or refreshes old source timestamps.
- Receipts record the selected dates while preserving the full original read for reconciliation. One read still permits one submission; read again before submitting another day from that range.
- Reopened receipts now lead with deletion-confirmed guidance and label the earlier failure as the original submission result. Returning from history scrolls to the date/read controls.
- Updated the agent instructions and knowledge to honor a user's request for fewer dates. The proposal schema remains version 1.

Verification: 55 rules checks, 80 mocked API/storage/submission checks, 22 updater checks, and packaged WPF checks. No live Quickbase records are created or deleted by these tests.
