# Timekeeper 0.4.1

- Fixed a false partial-submission error when Quickbase returns equivalent hours with different decimal formatting, such as `3.0` instead of `3`. Freshness checks now compare record values, so harmless formatting differences no longer stop subsequent rows.
- Retained strict checks for actual changes to hours, dates, projects, assignments, tasks, categories, descriptions and the record set.
- Improved stopped-submission receipts: they identify the next unsent row and preserve the reason, including changed record IDs/field names or a service error. Descriptions and raw response bodies are not echoed in change diagnostics.
- Added regression checks for decimal formatting, genuine edits, missing/additional records, read failures, and completing a partially submitted day without replaying created work.

## Recover a partial submission from an earlier version

1. Install this update. Keep the original receipt in Submission history.
2. If any row is **PENDING** or **UNKNOWN**, choose **Check selected result** and resolve that uncertain outcome before proceeding. If rows are only **CREATED**, **NOT_SENT** or **FAILED**, their outcomes are already known; a partial label alone does not mean an unknown write.
3. Read the same dates again and upload the new export to the shared Copilot agent. Identify which source entries the receipt confirms were created and ask for their `already_recorded` links to the supplied Quickbase records.
4. Have Copilot propose only the remaining source work. Timekeeper recalculates any Timecards/Misc internal additions using the fresh existing records. Review and acknowledge the existing-record links before writing the remaining rows.

Do not reuse the original proposal or delete the receipt. This update does not retry a write automatically. The existing schema-1 agent instructions and knowledge file remain compatible.

Verification: 48 rules checks, 60 mocked API/storage/submission checks, 22 updater checks, and the packaged WPF smoke checks. Diagnosis used a read-only Quickbase comparison; no live timecards were created by the diagnostic or tests.
