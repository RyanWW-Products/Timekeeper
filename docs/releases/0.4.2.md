# Timekeeper 0.4.2

Timekeeper can now prepare replacements for entries you intentionally deleted from Quickbase. Its local receipt previously blocked the original Toggl sources even when their Quickbase record was gone.

- In **Submission history**, select the original receipt and choose **Recover deleted entries**. Select only work entries you intentionally deleted, then confirm. The app checks the original record IDs across dates and employees, retains the creation results, and adds a dated deletion confirmation.
- Read the affected day again and send the new export to Copilot. Deleted records must not be marked `already_recorded`; records still present in the fresh export continue to count toward the day. Review the recalculated work, Timecards and Misc internal before writing.
- A fresh proposal is required after recovery. Unknown write outcomes, existing/restored record IDs, read errors and unsaved confirmations continue to block rewrites. Recovery itself never creates or deletes Quickbase records.
- Duplicate-source errors now identify the original Quickbase record and explain how to recover an intentionally deleted entry.
- The build script packages the current application version and refreshes `installer/Timekeeper-Setup.exe` with a verified copy. New installations start on 0.4.2 without an immediate update.
- Updated shared-agent instructions, knowledge and user help for this recovery workflow. The exchange schema remains version 1.

Keep the receipt files. For a whole-day rewrite, verify the old records are removed in Quickbase, recover the affected receipt entries, then read the day again. Do not reuse the earlier proposal.

Verification: 48 rules checks, 75 mocked API/storage/submission checks, 22 updater checks, and packaged WPF checks with 42 rendered views. Recovery coverage includes your corrected 3.25 + 2.83-hour day, restored/moved records, stale proposals, read/identity failures, unknown outcomes and failed receipt saves. No live Quickbase timecards were created or deleted by these tests.
